# 検証契約の改訂2

[English](verification-contract-v2.md)

`scope-operations-v2` では、カタログ7.0の72タスクのID、独立した2評価者、最低2確定ターンの
条件を維持し、公開する操作条件と検証Schemaを修正します。新しいrun IDを使い、
既存runは元のコード・カタログとともに保持してください。CPU fixtureの成功は、
自然画像全般での精度を証明するものではありません。

カタログ8.0（`scope-operations-v4`）ではタスクIDを改名・統合し、以下の規則は維持しています。
[カタログのガイド](README_ja.md#カタログ70からの変更)を参照してください。

## 質問の条件と根拠の分離

順位の比較では、数値回答用の小数桁上限を要求しません。目盛りのない軸の単位が省略されても、すべての正確な印字ラベルが `%` を含み、印字数値と抽出値が一致する場合だけ、その単位を対応付けます。この処理は数値検索やチャート復元には適用せず、ラベル不足・矛盾した単位・値の不一致は未解決のままにします。チャートの再試行では不正な領域の項目番号を示し、モデルの生出力や正解座標を渡したり、座標を自動補正したりしません。

- チャートでは、質問生成前に `rank_mode`（全順位・最大・最小・最大と最小）と
  `rank_order` を固定し、両評価者の抽出Schemaにも同じ条件を設定します。
  `max_min` は最大、最小の順で同順位をすべて含めます。`rank_order` は全順位の
  並び方を指定します。区間が十分に離れていれば最大・最小を証明できますが、
  正確な数値を読めたとは扱いません。重なる区間から大小を断定しません。
  抽出Schemaでは、目盛りなしの軸に目盛り値を入れる矛盾を拒否し、完全な
  抽出には系列・カテゴリの計算対象を要求します。`UNKNOWN` は空のまま返せます。
  チャート・図全体の抽出は表と同様に `tasks.source_max_tokens` を使い、固定の
  2,048トークンで一度途切れさせてから全体を再生成する無駄を減らします。
- ラベルのない点の位置表現は、閉じた集合で点が左右に分離している場合に限り
  登録した表現を照合します。両者の値・範囲・対応領域の一致が必要です。
  曖昧な位置や任意の類義語を自動的に同一視しません。
- 文書QAは、回答を見ずに、質問に答える最小限の完全な原文範囲を2回抽出します。
  原文の言語、限定、否定、例外を保持します。文頭の大文字・小文字と末尾の文の
  ピリオドだけを許容し、回答全体を照合します。部分一致・翻訳・限定の欠落は
  合格にしません。逐語転写・コード転写は引き続き完全一致で検証します。
- 数式の外側のLaTeX表示用囲みは許容しますが、記号・括弧・分数・指数などの
  構造を比較します。代数的な同値変形は転写成功にしません。行列、化学結合の
  二次元配置、未登録コマンドは未対応として保持します。
- 文字の転写では、質問生成前に既に宣言済みの囲み範囲へ結び付けます。回答後に
  領域を拡張しません。要求された単位全体の包含と独立した読み取りが必要です。
- グラフの接続・経路・辺の検証では、その計算に使わないノードの細分類の差を
  要求しません。ラベル、端点、方向、完全性、対応領域は引き続き検査します。
  二言語の回答で括弧内に可視ラベルを明記した場合は照合できますが、推測した
  翻訳や類義語では照合しません。

回答を見ない全source stageで、入れ子の `candidate_answer` も拒否します。
不完全な文書抽出では、確定したフィールドやノードを出力しません。図の線の
領域は、線の端点ではなく、横線・縦線でも正の面積を持つ実際の描線の囲みです。
根拠の欠落や不正形式を `MET` で補完しません。

チャート・グラフ・表・文書のsource decoderへ、既に公開したscopeの座標上限・下限を
渡します。転写・文書QAでは、指定済みのtarget領域を優先します。正の面積と包含は
復号後にも検査し、座標制約だけで可視性や完全性を認定しません。文書の題名や
軸名と物体のカテゴリも区別し、物体の根拠がなければ `object_label` はnullです。

## 表の公開出力仕様

出力文法を生成・評価の両方へ渡します。HTMLは実行・描画せずに解析し、内容と
形式を別々に判定します。対応タグは、正しく閉じた `table`、`thead`、`tbody`、
`tfoot`、`tr`、`th`、`td` と、セル内改行の `br` です。

セルの `rowspan`・`colspan`、見出しの `scope`、表の数値指定
`border`・`cellpadding`・`cellspacing` に対応します。`style` は公開した
`border-collapse`・`text-align`・`vertical-align` の選択肢に限定します。
未知のCSS、動的構文、イベント、外部素材は拒否します。文字、空欄、見出し、
行列位置、結合セルは独立した両読み取りとの一致が必要です。JSONのフィールドと
単純Markdownの制約も操作契約に含めます。

## 実行と計測

空白の上限指定には、検証済みvLLM 0.29.0のXGrammarパッチ、明示的な
`xgrammar`、通常の空白を許す設定が必要です。不一致は画像呼び出しを始める前に
設定読込で拒否します。架空のmanifestで通してはいけません。

停止記録は、実際に試行したターン番号を保存します。失敗・不正出力・再試行を
残し、通常のvLLMで要求上限を超えたusageは引き続きエラーにします。費用の欠測は
ゼロではありません。研究用native CLIのラッパー込み出力トークン数は、回答JSON
だけの数と確認できず、要求した生成上限も強制されません。上界実験ではこの
制約を残して解釈してください。

JSONの閉じ括弧が欠けた応答は補完せず拒否します。末尾に空白があっても、
元から完全な構造化JSONであれば既存の検証条件を適用します。

## 少数画像での速度比較

画像、モデルの割当、予定深度、seedを揃え、同じサーバー起動期間内で比較します。
`evidence_format: compact` はIDをcontrollerで付与します。
`initial_binding_batch_size: 2` は先頭候補を具体化し、有効な新しい事実がなければ
後続を試します。候補プールは8件を維持します。合格会話数、タスクの網羅、参照票、
出力トークン、再試行、実時間を併せて測ってください。並列HTTP時間の合計を実時間と
混同しません。いずれも品質ゲートを緩める設定ではありません。
