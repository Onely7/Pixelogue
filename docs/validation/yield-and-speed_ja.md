# 採用率と合成速度の比較手順

P0〜P8の比較実験の手順です。比較用設定でも最低2確定ターン、品質ゲート、候補上限8、
指定したモデル対を維持します。自動判定の `QUALITY_CANDIDATE` は人手承認済み会話では
ありません。計画上の最終監査は独立3名で行います。利用者が明示的に1名の暫定確認を
選んだ場合は、方針を記録し、結果を暫定として報告します。評価者間の一致は測定できず、
3名の監査を満たしたことにもなりません。開発用の評価票が完了しても、確認用の未提出票は
未測定のまま残します。

## 実行前に比較条件を固定する

コードを変更不能なアーカイブへ保存し、コミット、プロンプト、Schema、カタログ、検証器、
モデル・processorのrevision、入力hash、画像グループ、seed、言語、生成役割、予定深さを
記録します。各会話は同じ生成器を使い続けます。同じseedの反復も別run・別呼び出しとし、
同じ試行の再開だけ保存応答を再利用します。

実行・呼び出し識別には、実際のvLLM版、構造化出力backend、空白制御、server manifestの
hashも含めます。モデル、画像、公開操作、履歴、契約が変われば再利用できません。
非公開の盲検評価者の試行IDにより、モデルへ同じ入力を渡す別呼び出しを区別します。
共有endpointの別呼び出しは、異なる評価モデルの多様性の証明にはなりません。

最初に次の根拠抽出条件を比較します。

| 条件 | 根拠の形式 | 生成制御 |
|---|---|---|
| A | `keyed` | 現行の固定設定 |
| B | `array` | 現行の固定設定 |
| C | `keyed` | 明示backendと空白制御 |
| D | `array` | 明示backendと空白制御 |

backendも変更する場合は、設定一式の効果として解釈します。文字列内の空白、日本語、
エスケープした改行は別途確認します。arrayとcompactは視覚的説明・判定・領域を残し、
欠測をUNKNOWNのまま保持します。compactが省くのはcontrollerが付けるIDです。
以前の説明文短縮実験とは契約が異なります。

## 変更を一つずつ比較する

実験結果と人手品質が未確認の間は、次の既定値を維持します。

| 設定 | 既定 | 比較値 |
|---|---|---|
| `tasks.evidence_format` | `keyed` | `array` または `compact` |
| `tasks.attribute_recheck_enabled` | `false` | `true`、限定した再確認1回 |
| `tasks.fact_novelty_enabled` | `false` | `true` |
| `tasks.max_candidate_attempts` | `1` | `2` |
| `tasks.question_operation_guidance` | `baseline` | `object_identification_v1` |
| `tasks.initial_binding_batch_size` | `8` | `2` |
| `runtime.refill_completed_images` | `false` | `true` |
| `runtime.max_concurrent_images` | `2` | `4` |

条件・反復ごとに新run IDを使い、基準／候補の実行順を均衡させます。速度比較は同じ
モデル起動セッション内で行い、読み込み・終了処理の時間を明示的に配分します。
生成だけの時間も別に記録します。対象・領域の包含は安全な検証の契約です。
自動採用件数が下がっても、隣の対象の属性や拡大した根拠領域で通過させません。

事実の識別には明示された対象・属性・公開条件を使い、広い要求や曖昧な要求は不明に
残します。盲検の新規性ゲートも継続します。別候補への切替は同じ確定履歴と評価前の
順位を使い、失敗した質問・回答・判定を渡しません。根拠不明、回答失敗、通信障害では
候補を追加しません。

比較用の `object_identification_v1` は、通常V7の対象識別タスクの質問生成だけに適用します。
外観から確認できる粒度のカテゴリを求め、具体化済みの対象を保ち、ラベルの転写やUI機能の
説明との違いを明示します。非公開の正解カテゴリは生成器へ渡しません。選択器・評価者には
元の公開契約を渡し、正解の開示・質問・回答の既存ゲートをすべて維持します。
処理全体の比較で採用を判断するまでは実験用の設定です。

## 改善サイクルの終了条件を固定する

多様な開発画像100件と、診断用の約25件を固定します。100件の比較へ進む前に、変更を
25件で選別します。仮説と追加修正版の上限を事前に定めます。想定した改善の仕組みが
働かなかった変更は棄却し、失敗した呼び出しと費用を保存します。同じ高額な失敗を、
標本数を増やすだけの目的で繰り返しません。

実測した条件を一つ選び、別の生成seedで現行版と25件を比較してから、同じ100画像で
両条件を比較します。seed間でも予定深さを固定し、生成seedの変更で比較する会話長を
変えません。同じモデル起動セッションを使い、各ホストで実行順を均衡させ、画像ごとの
生成器割当を維持します。選別・別seed・最終比較は別々に報告します。別seedの実行も、
既に確認した画像を使う場合は開発用の試験です。

独立したAI参照評価を使う場合、回答票を開く前に質問票の判定を確定します。画像と公開
文脈の全hashが一致する票だけを再利用し、不明・未評価を保持します。モデル版を記録し、
AI参照と表示します。人手の正解や専門タスクの校正には代用しません。完成会話の全確定
ターンで、質問・回答の必要項目がすべて参照評価を満たした場合だけ、参照妥当な会話として
数えます。

先頭2候補で適格候補を得ると、後半の操作機会を省く可能性があります。時間とともに
候補への露出・タスク被覆を測ります。完了枠の補充では入力順の返却、会話内の履歴順、
同時実行数、待機バッファの上限を維持し、SQLite処理を直列化します。

## 失敗と未測定を含めて集計する

`pixelogue run-diagnostics` で段階の到達、試行ターン、確定ターン、終端会話を区別します。
`pixelogue task-status --junit` で共有CPU契約、タスク固有の境界、実GPUの回答例を
区別します。タスク登録やfixture合格だけでは自然画像の精度確認にはなりません。

次を分けて記録します。

- 実際のHTTP試行、内容の修正試行、通信再試行、キャッシュ利用。
- 正常／不正出力の判明usage、欠測usageの件数。
- 並列HTTP時間の合計、画像所要時間、実験実時間、モデル読み込み、終了処理、予約時間。
- 全結果の確定ターンと、完成した品質候補に含まれる確定ターン。
- 生成前停止、質問棄却、回答棄却、判断不明、実行エラー。

不正出力にも判明したusageを計上し、欠測をゼロにしません。再開では同じHTTP応答を
二重計上せず、二重確定もしないことを、生応答journal、予算、公開出力hash、commit数で
確認します。キャンペーン費用にはモデル読み込みと全予約GPUを含めます。同じGPUの
重なる時間区間は和集合で集計し、二重計上を防ぎます。

文章だけを扱う回答解析は、公開操作のview IDと保存済み質問の完全一致で画像・ターンへ
結び付けます。質問が一意に対応しない場合は深さを不明に残します。画像への対応が未解決の
呼び出しも全HTTP合計に含め、`unattributed_usage`へ所要時間・判明トークン・usage欠測件数を
別記します。

## 画像分布と実装の効果を分ける

Open Images validationの写真は、視覚説明・属性・空間・一部の集合操作を確認できますが、
文書・表・チャート・図・UI・専門タスクの被覆は保証しません。既に閲覧した画像は開発用
として扱い、調整前に新しい確認群を固定します。確認結果から再調整しません。

同じ画像源内での新旧差、タスク経路、深さ別の開始・到達、同じ採用ターン数での被覆を
報告します。画像グループ単位のbootstrapでは反復を一緒に保持します。画像源と内容が
同時に異なるため、源の間の差は記述的な比較です。検索語由来の分類は独立した操作機会
ラベルではありません。小さな構造画像の群は対応範囲の点検として扱います。

## 監査と移動可能な実例HTML

抽出manifest、手法・モデルの対応、自動判定、抽出確率は評価者へ配布する資料の外へ
保存します。可能なら画像グループごとに1会話を抽出します。必要な評価者全員が前の質問票を保存・
確定してから、次depthの質問票を配布します。後の公開履歴にある先行回答で、前の票を
変更しません。回答票は質問票の確定後に配布します。元票、不一致、裁定、不明、未評価を
保存します。

開発用と確認用の評価pack IDを分けます。完了した開発用の評価を、後で生成した確認用の
出力へ流用しません。明示された1名の暫定確認には[ローカル監査UI](../tasks/specialist-and-research_ja.md)
を使い、実際の評価票を保存します。集計CLIの既定は3名のままです。記録した暫定方針を
使う場合に限り、`--required-raters 1` を明示します。

回答が存在しない停止例は、完成会話の誤拒否率に入れません。母集団の集計には実際の
選択確率を使います。観測した層別抽出率だけでは、個々の選択確率を表せない場合があります。
空のテンプレートは人手票ではありません。

最終 `examples.html` は画像を埋め込み、新旧の実際の画像・指示・回答を表示します。
全72タスクを残し、実例がないタスクは欠測とします。停止会話の検証済み部分は診断用と
表示します。validation画像とその画像グループは評価専用を維持します。
